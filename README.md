# tfidf-lab — 핵심어 찾기 실험실

고등학교 인공지능수학 수업에서 쓰는 TF-IDF 계산기입니다.
브라우저에서 바로 열립니다. 설치할 것도, 인터넷 연결도 필요 없습니다.

## 무엇을 하는 도구인가

**세는 일과 계산은 도구가 맡고, 어떤 단어를 뺄지는 학생이 정합니다.**

한국어를 사전 없이 규칙만으로 정확히 토큰화하는 일은 원리적으로 불가능합니다.
조사 `가`와 명사 끝음절 `가`(전문가)는 문자열만 봐서는 구별되지 않고,
`밝혔다 / 밝히는 / 밝혀`를 하나로 묶으려면 형태소 분석기가 필요합니다.
규칙을 늘려도 오류가 옮겨 다닐 뿐 줄지 않습니다.

그래서 이 도구는 정확도를 끝까지 올리려 하지 않습니다. 대신

- **명사를 부수지 않는 것**을 우선하고,
- 남는 판단은 **불용어로 사용자에게 넘깁니다.**

무엇을 뺄지 고르는 일 자체가 TF-IDF 수업의 알맹이입니다.
문서의 성격에 따라 답이 달라지므로 정답을 코드에 박아 둘 수 없습니다.

## 쓰는 법

`index.html`을 브라우저에서 엽니다. 네 단계로 진행합니다.

**1단계 · 문서 고르기** — 세 가지 방법이 있습니다.
- **섹션별**: 경제·정치·사회·수학과학·인문·스포츠·연예 중 하나를 골라 여섯 편을 한 번에 담습니다.
- **테마별**: 섹션을 가로지르는 꾸러미입니다. 아래 설명을 보세요.
- **직접 넣기**: 학생이 가져온 문서를 붙여 넣습니다.

**2단계 · 읽어 보기** — 계산하기 전에 문서를 읽고 **주제어**(가장 많이 나올 것 같은 단어)와
**유용한 정보**(이 문서를 구별해 주는 단어)를 각자 적어 둡니다. 이 둘이 갈리는 것이 수업의 알맹이입니다.
결과를 먼저 보면 견줄 것이 없어집니다. 사람이 고른 것과 수식이 고른 것을
견주는 일이 이 수업의 알맹이입니다.

**3단계 · 계산 방법 정하기** — 기본값 그대로 두어도 됩니다. IDF를 비율형으로 할지
상용로그형으로 할지가 핵심 선택입니다.

**4단계 · 결과 보고 다듬기** — 표에서 단어 옆 **&times;** 를 누르면 빠지고,
「빠진 단어」에서 단어를 누르면 되살아납니다. 빼고 다시 보고 되살리는 반복이
이 단계의 전부입니다.

## 수업에서 보여 줄 수 있는 장면

**섹션 여섯 편을 넣으면** — 그 분야의 공통 단어(경제라면 `물가`, `기업`, `시장`)가
여섯 편 모두에 나옵니다. DF가 6이 되어 IDF가 0으로 떨어지고 점수도 0이 됩니다.
경제 기사 여섯 편에서 `물가`는 **가장 많이 나온 단어(주제어)인데 유용한 정보는 되지 못합니다.**
대신 `소비자물가`, `환율`, `유가`가 올라옵니다.

> 많이 나온 단어가 **주제어**이고, 여기서만 많이 나온 단어가 **유용한 정보**다.

**테마 다섯 편을 넣으면** — 섹션이 다섯 개로 갈라지지만 갈래 단어는 공유합니다. 섹션 묶음보다 한 편 적습니다.
「인공지능과 데이터」를 넣으면 `데이터`와 `인공지능`만 IDF 0이 되고
나머지는 모두 살아남습니다. 같은 문서라도 **어떻게 묶느냐에 따라 유용한 정보가 달라집니다.**

**「뉴스체 서술어」 묶음을 켜 보면** — `밝혔다`, `올랐다`처럼 기사에 늘 나오는
서술어가 한 번에 사라집니다. 켜기 전과 후의 순위를 견주어 보게 하세요.

**IDF를 상용로그형으로 바꿔 보면** — 모든 문서에 나오는 단어의 IDF가 1에서 0으로
떨어져 점수가 아예 사라집니다. 기본값은 교과서를 따라 비율형(`N / DF`)이고,
로그는 문서가 아주 많을 때 왜 필요해지는지를 보여 주는 장치로 두었습니다.
3단계에 「실제로는 왜 로그를 씌울까」를 접이식으로 넣어 두었습니다 —
교과서와 같은 이유, 곧 **수가 너무 커져서 계산이 불편해진다**는 점을
`n = 10^6, DF = 10^2 → n/DF = 10^4 → log 10^4 = 4` 표로 보여 줍니다.

## 예시 문서에 대하여

**42편 모두 수업용으로 지어낸 문서입니다. 실제 보도가 아닙니다.**
실존하는 인물, 기업, 기관, 통계를 담고 있지 않으며 등장하는 기관 이름은
모두 `가상`으로 시작합니다. 화면에도 「가상 기사」 표시가 붙습니다.

인터넷에서 수업에 쓸 만큼 정제된 문서를 찾기가 생각보다 어려워 미리 갖춰 둔 것입니다.
문서마다 **70~130개의 단어**가 남도록 썼고(실측 81~119, 중앙값 97),
같은 섹션끼리는 공통 단어를 나눠 쓰도록 일부러 설계했습니다.

길이는 교과서와 타협한 값입니다. 교과서 예제는 문서 하나가 한 문장이라
손으로 검산하기는 좋지만 DF가 갈리지 않아 IDF가 0으로 떨어지는 장면을 볼 수 없습니다.
반대로 실제 기사 길이로 가면 학생이 읽다가 지칩니다. 한 편을 2~3분에 읽고
여섯 편을 견줄 수 있는 지점을 잡았습니다.

## 계산 방식

| | 이름 | 뜻 |
|---|---|---|
| TF | 단어빈도 | 각 문서에서 그 단어가 나오는 **횟수** |
| DF | 문서빈도 | 각 단어별로 그 단어가 나오는 문서의 개수 |
| IDF | 역문서빈도 | `전체 문서의 개수 / DF` (기본) 또는 `log10(N / DF)` |
| TF-IDF | | TF × IDF |

**고등학교 인공지능수학 교과서의 정의와 용어를 그대로 따릅니다.**
IDF에 로그를 씌우는 방식은 문서가 아주 많을 때 필요해지는 것이라
교과서에서도 참고 자료로 다룹니다. 이 도구에서도 선택 사항으로 두었습니다.

**TF는 횟수를 그대로 씁니다.** 고등학교 인공지능수학 교과서의 정의를 따른 것입니다.
횟수를 문서 길이로 나누는 상대 빈도도 문헌에 나오는 정식 정의지만, 그렇게 하면
학생이 교과서 예제를 손으로 풀었을 때와 숫자가 달라집니다.

대신 긴 문서일수록 모든 단어의 TF가 커진다는 점은 화면에서 짚어 줍니다.
문서 길이는 「세어 본 결과」에 적어 두었으니 견줄 때 함께 보세요.
이 성질을 두고 "왜 길이로 나누는 방식이 따로 있을까"를 묻는 것도 수업 거리가 됩니다.

화면에는 값과 함께 **계산 재료를 적어 둡니다.** TF-IDF 칸에는 `3회 × 0.6990`,
IDF 칸에는 `log10(5 / 2)`처럼요. 학생이 손으로 검산할 수 있습니다.

## 단어를 빼고 되살리기

이 도구에는 설정 체크박스가 거의 없습니다. **뺀 것은 무엇이든 단어 하나씩
되살릴 수 있기 때문에** 미리 정해 둘 이유가 없습니다.

도구가 자동으로 빼는 것은 셋입니다.

| 이유 | 예 |
|---|---|
| 서술어 | `있습니다`, `하겠습니다` |
| 한 글자 단어 | `수`, `것` |
| 숫자만 있는 단어 | `0.3`, `2026` |

여기에 불용어 묶음 세 가지(일반 한국어 · 뉴스체 서술어 · 수와 단위)를 켜고 끌 수 있습니다.
`밝혔다`, `올랐다` 같은 뉴스체는 규칙으로 잡지 않고 묶음이 맡습니다.

**묶음을 켠 채로 그 안의 단어 하나만 되살릴 수 있습니다.** 묶음을 펼쳐 단어를 누르거나
「빠진 단어」에서 누르면 됩니다. 90개짜리 묶음에서 하나를 살리자고 나머지 89개를
함께 되살릴 수는 없으니까요.

## GitHub Pages 배포

정적 파일뿐이라 그대로 올리면 됩니다.
`Settings → Pages → Source`에서 `Deploy from a branch`, 브랜치 `main`, 폴더 `/(root)`.

**고친 내용이 바로 안 보일 때** — GitHub Pages가 파일마다 10분짜리 캐시
(`max-age=600`)를 붙입니다. 방금 올린 수정이 화면에 반영되지 않으면 캐시 탓입니다.
`Ctrl+Shift+R`(맥은 `Cmd+Shift+R`)로 강제 새로고침하거나 10분 뒤에 다시 여세요.
수업 직전에 고쳤다면 미리 한 번 강제 새로고침해 확인하는 편이 안전합니다.
